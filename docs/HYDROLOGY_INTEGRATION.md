# GulfScope hydrology integration

## GPM IMERG / POWER daily UTC

The archived request used the monthly POWER point endpoint with community AG. It returned HTTP 200, units mm/day, time standard LST, no named source, and only the -999 fill value. The hydrology catalog table suggests monthly/climatology availability, but the dedicated [POWER IMERG specification](https://power.larc.nasa.gov/docs/methodology/data/sources_meteorology/#imerg) says POWER serves these data at daily UTC only. The live daily endpoint also rejected community HY (422), and rejected the documented optional retrieval-count alias in the AG probe. The supported request was `/api/temporal/daily/point`, `parameters=IMERG_PRECTOT`, `community=AG`, `time-standard=UTC`, and eight-digit dates. RE and AG returned the same seven Bahrain pilot values February 1–7, 2025 (February 6: 2.6, other days: 0). The full archive reproduced that sample.

Six new raw archives and SHA-256 metadata preserve the original response bytes for January 1, 2001 through December 31, 2025. Each has 9,131 valid daily observations, 300 complete months, and 25 complete years. The service identifies the source as IMERG and labels daily values mm/day; NASA describes each as a UTC daily total obtained by summing half-hourly depths, in mm. Each reported value spans exactly one day, so its value in mm/day represents the same numerical depth in mm over that day. Monthly and annual datasets report sums in mm, not average rates. Verification independently compares each published total to the archived daily values and checks the pilot against separately retrieved requests to the same provider. This is not validation against an independent instrument.

Require every valid UTC day in a calendar month, including February 29 where applicable. Require every complete month in a calendar year. Reject nonphysical values and unexpected date keys; absent, null, or fill-valued days make their periods incomplete. Do not substitute zeros or interpolate. The exact coordinates are POWER requested points. NASA documents a 0.1° grid; this route does not return the sampled native cell centre, land/water fraction, exact algorithm version, or processing run. Records end well before the documented Late/Final overlap near retrieval, but the body does not confirm an explicit run ID. Coastal samples can mix land and water. Do not equate UTC IMERG and local-solar-day POWER/MERRA-2 conditions.

`node scripts/archive-power-daily.mjs imerg <site> [...]` retrieves immutable archives for a new supported site. It refuses to overwrite an existing body or metadata file. Builds use only local archives.

## SMAP Level-4 / NASA POWER high-resolution archive

The old monthly LST AG requests returned only -999 and no source. Daily UTC AG requests for `SFMC,RZMC` also returned only fill at Bahrain and Riyadh; a separate RE CSV request at Riyadh described the parameters as MERRA-2. Neither the hypothetical `SMAP_SFMC` nor `SFMC_SMAP` alias was accepted. The public point endpoint therefore did not establish SMAP provenance. The proximate reason for rejecting the previous probes is lack of valid SMAP values and source identification; NASA did not expose the backend reason for the blank result.

GulfScope instead reads the official high-resolution [NASA POWER daily UTC SMAP Zarr archive](https://nasa-power-smap.s3.amazonaws.com/smap/temporal/power_smap_daily_temporal_utc.zarr/.zmetadata). NASA documents a native approximately 9 km EASE grid and regridding to approximately 0.09° POWER latitude–longitude spacing. The extraction uses the nearest stored latitude and longitude independently, using the actual coordinate arrays. It never searches for a neighbouring land cell or interpolates. The exact requested and sampled coordinates are distinct and are both retained. The archive marks both variables as reviewing; its metadata reports POWER version 10.0.0 rather than a specific upstream SMAP product version.

Each site has 3,928 valid daily values per variable out of 3,929 requested from 2015-03-31 through 2025-12-31. SFMC describes 0–5 cm; RZMC describes 0–100 cm. Both are stored as volumetric m³/m³ and describe satellite-constrained model estimates. September 20, 2025 is missing for both variables at every site. March 2015 is partial. Only complete UTC months and years are averaged (128 months and nine years per variable, annual coverage 2016–2024). The Field Desk shows the records descriptively and withholds slope, confidence intervals, and significance under the existing 20-complete-year rule. Do not splice these values to MERRA-2.

Reproduce the extraction offline with `python scripts/extract-smap-daily.py` in an environment with NumPy and numcodecs. The optional `--download` fills absent objects and never overwrites existing bytes. The extraction checks byte-for-byte reproducibility; the build checks SHA-256 against the original compressed objects and derives the aggregates locally without requiring Python. A spot check against NASA's separately stored daily spatial layout matched both variables at all six sites on 2025-02-06 and confirmed the missing 2025-09-20 day (absent spatial chunks whose declared fill is NaN). This checks the extraction against an independent layout of the same product, not against ground measurements.
